# انتشار RustGIS از طریق همگام‌سازی Cron هاست

## روش انتشار
سایت از مسیر GitHub به کمک Cron موجود در cPanel همگام‌سازی می‌شود. بنابراین خروجی‌های کامپایل‌شده WebAssembly نیز باید فایل‌های واقعی داخل پوشه `sabzroyanuraman-site` باشند؛ GitHub Actions Artifacts به‌تنهایی توسط Cron دریافت نمی‌شوند.

Workflow زیر پس از ادغام تغییرات به شاخه `master`، هر دو موتور Raster و Vector را تست و برای مرورگر کامپایل می‌کند، خروجی‌ها را داخل پوشه سایت قرار می‌دهد و آن‌ها را در یک commit ثبت می‌کند:

`/.github/workflows/rustgis-cron-publish.yml`

پس از ادغام به `master`، تغییر سورس Raster/Vector یا خود Workflow به‌صورت خودکار `push` را فعال می‌کند؛ Workflow هر دو موتور را تست و build کرده و فایل‌های خروجی را commit می‌کند. Cron موجود پس از آن فایل‌ها را به `public_html` منتقل می‌کند. اجرای دستی `workflow_dispatch` نیز برای بازسازی اضطراری باقی است. برای این روش، FTP/FTPS و Secretهای FTP لازم نیستند.

## مسیر خروجی‌ها
- Raster: `sabzroyanuraman-site/wasm/rust-raster/`
- Vector: `sabzroyanuraman-site/rustgis-vector-wasm-pkg/`

## نکات
- فایل‌های JavaScript واسط در خود پوشه سایت نگهداری می‌شوند و همراه همگام‌سازی معمول منتقل خواهند شد.
- فایل‌های WASM فقط هنگام تغییر سورس یا اجرای دستی Workflow بازسازی و commit می‌شوند؛ نیازی به آپلود دستی یا انتقال مکرر نیست.
- Workflow فقط روی `master` به‌صورت خودکار اجرا می‌شود. اجرای دستی از `workflow_dispatch` روی شاخه انتخاب‌شده نیز ممکن است؛ در آن حالت خروجی در همان شاخه ثبت می‌شود.
- این تغییر به‌تنهایی به معنی انتشار روی هاست نیست؛ ابتدا PRهای مربوط باید طبق ترتیب وابستگی ادغام شوند و سپس اجرای موفق Workflow و همگام‌سازی Cron بررسی شود.
- هیچ تغییری در تنظیمات FTP/WHM لازم نیست.
