# بسته‌های کاری اولویت‌دار پروژه کارگزاری — 2026-10-18

## هدف و محدودیت‌های ثابت

این برنامه بر اساس وضعیت فعلی شاخه و سند `الزامات_کارگزاری.html` تنظیم شده است؛ برنامه، تأییدیه انطباق یا مجوز بهره‌برداری نیست.

- شاخه کاری: `codex/project-readiness-baseline`.
- `master` ادغام یا تغییر داده نمی‌شود و این شاخه حذف نمی‌شود.
- پرداخت .NET غیرفعال می‌ماند؛ مسیر پرداخت PHP سایت تغییر نمی‌کند.
- مراحل و قواعد اختصاصی S01/S02/S03 فقط از اسناد مصوب هر خدمت استخراج می‌شوند؛ نبود مشخصات با حدس جبران نمی‌شود.
- هر بسته باید تغییرات محدود، معیار پذیرش و شواهد CI/آزمون مستقل داشته باشد. CI سبز به‌تنهایی تأییدیه سازمان یا آمادگی Production نیست.

## بسته قابل پیشبرد در همین شاخه

1. حفاظت از مرزهای انتشار را با تست‌های موجود حفظ کن؛ تغییرات مرتبط را با هم بازبینی کن.
2. ردیابی S01/S02/S03 را در `docs/SERVICE_REQUIREMENTS_TRACEABILITY_S01_S03.md` به‌عنوان نقشه شکاف نگه دار. این سند جایگزین مشخصات اختصاصی مصوب نیست.
3. تست‌های موجود S02/S03 فقط پایه ایجاد/خواندن، احراز هویت، مالکیت و no-store را ثابت می‌کنند؛ این خدمات تا تأیید مراحل و قراردادها «کامل» علامت نمی‌خورند.
4. تست‌های موجود S01 مرز تراکنش محلی را پوشش می‌دهند؛ پذیرش موفق سازمان و ذخیره محلی یک تراکنش اتمیک مشترک نیستند. بدون قرارداد رسمی، retry خودکار یا جبران‌سازی حدس زده نشود.
5. پس از یک دسته تغییر مرتبط، یک pipeline برای آخرین commit شاخه اجرا شود؛ نتیجه فقط برای همان SHA گزارش شود. pipelineهای commitهای قبلی جایگزین آن نیستند.

## ورودی‌های لازم برای باز کردن بسته‌های مسدود

- سند الزامات مصوب و نسخه‌دار هر یک از S01، S02 و S03، شامل فیلدها، مدارک، مراحل، خطاها و معیار پذیرش.
- قرارداد API رسمی سازمان و قرارداد correlation/idempotency/status lookup.
- مشخصات/دسترسی مجاز Sandbox برای ثنا، شاهکار، IAM، ثبت و سرویس‌های مکانی.
- مصوبه پایگاه داده Production، سیاست ZDR/نگهداری و مسئول تأیید تعرفه و مالکیت پرداخت.

تا وقتی این ورودی‌ها فراهم نشده‌اند، کار درست تکمیل کنترل‌های عمومی، آزمون‌های مرزی و مستندسازی شکاف‌هاست؛ نه اختراع گردش‌کار تجاری یا فعال‌سازی پرداخت.
