# ردیابی الزامات S01، S02 و S03

نام خدمات طبق اعلام مالک پروژه: S01 تهیه نقشه؛ S02 درج گواهی اقدام؛ S03 درج ادعای موضوع ماده ۱۰ قانون.

فایل `الزامات_کارگزاری.html` شامل الزامات عمومی شیوه‌نامه و پیوست فنی است؛ در آن مشخصات اختصاصی هر سه خدمت (ورودی‌ها، مدارک، گردش‌کار، API و معیار پذیرش) یافت نشد. ماده ۲ بند «خ» شیوه‌نامه می‌خواهد حداقل سه خدمت مطابق اسناد الزامات خود پیاده و به تأیید معاونت فناوری برسند. بنابراین هیچ قانون تجاری یا مرحله‌ای حدس زده نمی‌شود.

## بندهای عمومی قابل ردیابی
- پیوست فنی فصل دوم، «فرآیند محوری»: مراحل باید عیناً مطابق فرایند مصوب سازمان باشند.
- فصل دوم «سرویس‌گرایی» و فصل ششم: فقط API رسمی سازمان، توکن IAM، مدیریت خطاهای 4xx/5xx و محدودیت نرخ؛ دسترسی مستقیم به پایگاه داده سازمان ممنوع.
- فصل پنجم و ششم: MFA/OTP و احراز هویت غیرحضوری از طریق ثنا و تطبیق شماره همراه با شاهکار؛ در صورت عدم احراز شرایط، توقف فرایند.
- فصل دوم «عدم رسوب داده»: داده حساس/حاکمیتی دائمی در DB یا فایل کارگزار ذخیره نشود؛ استفاده موقت و پاک‌سازی پس از انجام تراکنش.
- فصل چهارم: پایش ۲۴/۷، داشبورد فقط‌خواندنی سازمان، SLA حداقل ۹۹.۵٪، DR با RTO/RPO مشخص و لاگ استانداردِ امن و غیرقابل‌تغییر حداقل ۶ ماه با قابلیت ارسال به SIEM.
- فصل ششم: پرداخت فقط از درگاه مستقیم متصل به حساب حقوقی کارگزاری؛ درگاه واسط ممنوع.
- فصل هفتم: سازمان حق ممیزی فنی و امنیتی دارد.
